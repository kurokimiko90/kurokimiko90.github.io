Caption formula

01 / NAME這張圖是什麼。
02 / PURPOSE它解決哪個問題。
03 / CONTRIBUTION本人負責哪個部分。
04 / EVIDENCEVerified、Observed 或 Reconstructed。
圖片 QA所有圖片必須具備 alt；先設定 aspect-ratio 避免 CLS；首屏主圖 eager，其餘 lazy；手機版保持完整構圖並改為單欄，不使用會裁掉關鍵 UI 的 center crop；lightbox 開啟時立刻移動 keyboard focus。

03 / PRODUCT DIAGRAMS

圖不是附件，是判斷的介面。

案例中的流程圖與產品結構圖，必須先說清楚「要回答哪個問題」。保留真實複雜度，但用焦點色、動詞箭頭與圖後結論，讓招聘主管不用解讀白板原稿。

01 / QUESTION

先寫閱讀問題

標題下用一句話界定圖的目的，例如「第三方服務失敗時，流程如何繼續？」

02 / MAP

只保留一層關係

一張圖只講流程、結構或旅程其中一種；需要跨層時拆成第二張圖。

03 / FOCUS

高亮本人判斷

品牌藍只標示關鍵決策、改造點或目前討論範圍，不代表一般裝飾。

04 / TAKEAWAY

圖後立即下結論

用兩句話說明看到了什麼，以及這張圖如何改變優先級、規格或協作。

規則標準原因
一圖一問流程／結構／旅程三選一；主節點建議 5–7 個案例頁是用來快速理解判斷，不是保存完整 workshop 白板。
顏色有語意藍＝本人決策；灰＝外部或背景；虛線＝任意、未驗證或備援同一份作品集中保持可預測，不以彩虹色區分類別。
箭頭寫動詞標示「通過」「失敗」「保存」等條件；不畫無意義連線讓讀者理解狀態如何改變，而不只是元件靠得很近。
證據要分級Verified / Observed / Hypothesis / Reconstructed 固定放右上角避免重構圖被誤認為實際產品畫面或研究結論。
手機不縮成縮圖保留 1000px 以上畫布與水平捲動；圖前後文字維持單欄文字不得小於 12px，也不能因裁切失去流程分支。
在案例頁的位置先用 1–2 段文字說明 Context / Constraint，再放圖；圖後緊接 Decision / Trade-off。不要在 Hero 放複雜流程，也不要把圖藏在 lightbox 裡。完整大圖可以開啟，但頁面內必須先看得懂主結論。

DO / 用動畫維持脈絡

案例卡片展開時從觸發位置進入；圖片 lightbox 維持原圖與大圖的空間關係；焦點在動畫開始時立即移動。

DON’T / 不製造表演

不做無限漂浮、整頁 parallax、逐字打字、快速閃爍或每張卡片輪流飛入。動畫不得阻塞閱讀或導覽。

Reduced motion偵測 prefers-reduced-motion: reduce 後，所有 duration 變成 0ms；內容預設可見、焦點與資訊層級完全不依賴動畫。

Reference principles

  • Design tokens：以語意而非顏色值命名，作為介面決策的單一來源。
  • Spacing：採 8px 基準與有限間距尺度。
  • Typography：可讀性、層級與 rem 響應式。
  • Motion：Human、Clarity、Accessible、Performant。
  • Applying motion：互動 50–150ms、轉場 150–400ms，進場比離場更完整。
